# 0002. Хранение данных in-memory, без базы данных

**Статус:** принято

**Контекст:** учебный проект «Запись на звонок»: бронирования, типы встреч и слоты нужно хранить как-то, но БД добавляет инфраструктуру (установка, миграции, окружение), не связанную с целиком задачей курса.

**Решение:** все данные хранятся только в оперативной памяти процесса сервера (обычные JS-объекты). БД, файловое сохранение и ORM не подключаются без явного запроса пользователя.

- Хранилище изолировано в одном модуле `server/src/store.js` — при необходимости заменяется на БД без изменения остального кода.
- При каждом старте/сбросе хранилища создаются два типа встреч по умолчанию («Созвон на 30 минут», «Созвон на час»), чтобы запись была доступна сразу.
- Тесты сбрасывают состояние хранилища перед каждым тестом.

**Последствия:** данные не переживают перезапуск — ни рестарт контейнера, ни новый деплой, ни засыпание free-инстанса Render. Ограничение задокументировано в README («Хранение данных»).

**Источники:** README «⚠️ Хранение данных — важно»; спека #1 (Notes: in-memory хранилище — фиксированное входное правило).
