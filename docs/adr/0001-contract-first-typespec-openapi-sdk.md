# 0001. Contract-first: TypeSpec → OpenAPI → клиентский SDK

**Статус:** принято

**Контекст:** фронтенд и бэкенд разрабатываются раздельно и должны согласоваться на уровне API. Большой OpenAPI-файл вручную поддерживать тяжело и легко разойти с реальностью; у фреймворка (Express) нет официального генератора артефактов из OpenAPI.

**Решение:** единственный источник правды об API — TypeSpec-контракт `contract/main.tsp`. Пайплайн: `contract/main.tsp` → (`tsp compile`) → `contract/openapi.yaml` → (`openapi-ts`) → `client/src/api/generated/`. Оба шага выполняются одной командой `mise run generate`.

- `contract/openapi.yaml` и `client/src/api/generated/` — генерируемые файлы, руками не правятся (запрет записан в AGENTS.md, сверяется в CI задачей `verify:generated`).
- Генератора серверных артефактов под Express нет — сервер реализуется по `openapi.yaml` вручную, совпадение проверяют API-тесты (коды, тела успешных ответов, `400`/`409`).
- Фронтенд обращается к API **только через сгенерированный SDK**: ручной `fetch('/api/...')` запрещён ESLint-правилом.

**Последствия:** изменение API всегда начинается с правки TypeSpec, затем генерация, затем код обеих сторон. Расхождения обнаруживаются на проверке типов и в API-тестах, а не на живом приложении.

**Источники:** README «Контракт API: TypeSpec → OpenAPI → SDK»; тикет #9 («Контрактная цепочка и единая команда проверок»).
