# 0003. Запрет пересечений: полуоткрытые интервалы и атомарная проверка

**Статус:** принято

**Контекст:** два бронирования не должны занимать одно и то же время. Проверка только во фронтенде обходится любым другим клиентом (прямой запрос в API создаст вторую запись). Параллельные запросы от двух гостей могут «пройти» между проверкой и записью, если между ними появляется `await`.

**Решение:**

- Интервалы полуоткрытые `[start, end)` — встреча может начинаться ровно в момент окончания предыдущей (back-to-back разрешён), любое частичное наложение запрещено.
- Запрет действует **независимо от типа встречи**: пересечение разных типов — тоже конфликт (`409`).
- Проверка пересечения и создание брони выполняются **атомарно** — одной синхронной операцией без `await` между проверкой и записью (Node.js однопоточен, check-and-set нельзя разрывать асинхронными вызовами).

**Последствия:** правило живёт только на сервере (`server/src/schedule.js` → функция `overlaps`, `server/src/routes/bookings.js`); гость при конфликте получает `409` и сообщение «Это время уже занято». Чувствительность теста подтверждена мутационной проверкой в тикете #13 (красный/зелёный запуск).

**Источники:** README «Доменные правила» (пункты «Запрет пересечений», «Конкурентность»); тикет #13.
